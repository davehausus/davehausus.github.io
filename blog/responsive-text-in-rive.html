Rive Responsive Text: How to Scale Typography Across Breakpoints


Designing dynamic motion shouldn’t require being a JavaScript wizard. Here is how I got responsive text working in Rive: what I learned, what broke, and how it finally came together.

by David de Jesús

Motion on the web has changed dramatically. We are no longer shipping heavy videos or grainy GIFs. Tools like Rive bring app-level motion to any website with tiny file sizes, real-time animation, and even dynamic text, as long as you know how to connect everything.

As a designer, that last part was the challenge. I did not know how to connect everything. Responsive text inside a Rive animation sounded simple enough, until I actually tried to build it.

This article breaks down the setup I ended up using. It is written in human language, not developer language, so you can understand it even if you do not write code every day.

Why Responsive Text in Rive Is Tricky

Rive animations live inside a canvas element. The canvas does not automatically know the size of the page around it, and Rive does not detect layout changes the way CSS does.

So when your layout gets narrower on mobile or wider on desktop, the animation stays the same unless you manually tell it two things:

  1. How big the canvas is.
  2. How big the text inside Rive should be.

To bridge that gap, Rive uses something called a View Model. You can think of it as a small communication channel where you send values from JavaScript into your Rive file.

If we pass the canvas width into Rive, we can tell the text how big it should be.

That was the breakthrough.

The Setup: Passing Real Page Width into Rive

Let us look at the important parts of the code. Instead of explaining what each line does on a technical level, I will explain what the code means in plain language from the perspective of a designer trying to make dynamic text work.

1. We start by grabbing the canvas
const canvas = document.getElementById("riveCanvas");

This tells the animation where it will live on the page.

2. We initialize Rive with the settings we need

const r = new rive.Rive({
  src: "your_rive_file_name.riv",
  canvas: canvas,
  autoplay: true,
  autoBind: true,
  loadRiveFile: true,
  artboard: "Artboard",
  stateMachines: "State Machine 1",
  useDataBinding: true,
  layout: new rive.Layout({
    fit: rive.Fit.Contain,
    alignment: rive.Alignment.CenterLeft,
  }),
});

Here is the human explanation:

  • autoplay starts the animation automatically
  • useDataBinding allows you to send values into Rive
  • layout.fit and alignment define how the animation scales in the canvas
  • loadRiveFile: true is required if you want WebGL and View Models to work together

This block is the connection point between your website and your Rive file.

3. When the Rive file loads, we grab the View Model

onLoad: () => {
  const vmi = r.viewModelInstance;

The View Model is like the control panel inside your Rive file.
If this does not load, none of the dynamic parts will work.

4. We get the View Model number property in Rive called "num"

Inside the Rive file, I created a number property named num.
This property receives the width of the canvas. 


const numProp = vmi.number("num");

Inside Rive, the num value drives text size.
Outside Rive, JavaScript updates that value whenever the layout changes.

This is the entire idea behind data binding.

Making It Responsive

Here is where everything comes together. We update the size of the canvas and send that size into Rive so the text can scale based on the layout.

5. We calculate the canvas size and send it into Rive

This function measures the real width of the container on the page, resizes the canvas, and then passes that width into the Rive View Model.


function updateCanvasWidth() {
  if (isResizing) return;
  isResizing = true;

  const currentWidth = canvasParent 
    ? canvasParent.clientWidth 
    : canvas.clientWidth;

  const aspectRatio = 1110 / 450;

  canvas.style.width = currentWidth + "px";
  canvas.style.height = (currentWidth / aspectRatio) + "px";

  numProp.value = currentWidth;

  requestAnimationFrame(() => {
    r.resizeDrawingSurfaceToCanvas();
    isResizing = false;
  });
}

This part felt like magic when I finally understood it. The canvas is resized according to the layout, and the new width is sent into the num property inside Rive. Now the text reacts to the design around it.

6. We run the function once on load
updateCanvasWidth();

This ensures your animation looks correct the moment the page loads.

7. We listen for window resizing

If the user resizes the browser or rotates their phone, we update the canvas and tell Rive about the new width.


let resizeTimeout = null;

window.addEventListener("resize", () => {
  clearTimeout(resizeTimeout);

  resizeTimeout = setTimeout(() => {
    updateCanvasWidth();
  }, 120);
});

The delay prevents the browser from running hundreds of updates per second. This keeps everything smooth and stable.

What Happens Inside Rive

Once the width value arrives in Rive, you can connect it to a text size or a blend state. This means your animation is no longer static. It becomes responsive and adjusts to the space it lives in.

You can use the incoming number in many ways:

  • Change text size as the screen gets smaller
  • Scale elements that need to remain legible on mobile
  • Drive animation states based on layout conditions

This approach gives you full control over how typography behaves in your motion design, something that traditional video formats can never do.

A Designer’s Takeaway

I went into this wanting something simple. I wanted the text inside my Rive animation to adjust naturally when the layout changed. What I did not expect was to learn how canvas sizing works, how Rive reads data, and how JavaScript can connect both worlds.

The good news is that once you set this up, it becomes a reusable pattern. You can build responsive animations, dynamic typography, and motion that adapts to any viewport size.

If you design interfaces with motion, this unlocks a new level of flexibility. It lets your animations feel like part of the product, not something pasted on top.

Final Code Block

Here is the complete script ready to paste into your project.


<script>
  const canvas = document.getElementById("riveCanvas");

  const r = new rive.Rive({
    src: "your_rive_file.riv",
    canvas: canvas,
    autoplay: true,
    autoBind: true,
    loadRiveFile: true,
    artboard: "Artboard",
    stateMachines: "State Machine 1",
    useDataBinding: true,
    layout: new rive.Layout({
      fit: rive.Fit.Contain,
      alignment: rive.Alignment.CenterLeft
    }),

    onLoad: () => {
      const vmi = r.viewModelInstance;
      if (!vmi) return;

      const numProp = vmi.number("num");
      if (!numProp) return;

      const canvasParent = canvas.parentElement;
      let isResizing = false;

      function updateCanvasWidth() {
        if (isResizing) return;
        isResizing = true;

        const currentWidth = canvasParent 
          ? canvasParent.clientWidth 
          : canvas.clientWidth;

        const aspectRatio = 1110 / 450;

        canvas.style.width = currentWidth + "px";
        canvas.style.height = (currentWidth / aspectRatio) + "px";

        numProp.value = currentWidth;

        requestAnimationFrame(() => {
          r.resizeDrawingSurfaceToCanvas();
          isResizing = false;
        });
      }

      updateCanvasWidth();

      let resizeTimeout = null;
      window.addEventListener("resize", () => {
        clearTimeout(resizeTimeout);
        resizeTimeout = setTimeout(() => {
          updateCanvasWidth();
        }, 120);
      });
    }
  });
</script>

Closing Thoughts

Responsive motion is no longer optional. Interfaces now need to feel alive across every screen size, and that includes typography inside your animations. This method allows you to design motion that breathes with the layout, adapts with the user, and stays connected to the system it belongs to.
